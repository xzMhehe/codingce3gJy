# 军官系统改动说明（2026-10-06）

> 一共 5 条改动，全部**已改代码 + 已本地验证**，等你自己打包部署。
> 线上库已经预先补好新代码硬依赖的列（见第三节）。

## 一、五条改动

### ① 军校招募的军官，落库军官池 id

- **问题**：`hireOfficerDraft` 里写死 `GeneralId: 0`，招募出来的军官和军官池没有关联 ——
  改名之后连「按名字回查池子」都找不回来，丢官/被俘后没法追溯是哪一条池子军官。
- **改法**：候选本身就从军官池抽（`rollOfficerDrafts`），draft 里已经带 `PoolId` →
  落库直接写 `GeneralId: pick.PoolId`。（池子为空的兜底随机候选 `PoolId=0`，仍是 0。）
- ⚠️ **配套口径**：以后「是不是名将」一律用 `ezfyCfg.isGeneral(id)`（池子 `kind==2`）判定，
  **不要再用 `GeneralId > 0` 当名将标志**（普通军官现在也有 id 了）。
- **已处理的副作用**：活动野地守将「同一玩家可抓次数上限」的计数，
  加 `AND source <> 2` 排掉军校招募来源，保持改动前口径。
- 历史老数据（2026-10-06 前招的）`general_id` 仍是 0，名字回查保留作兜底。

### ② 军官一律逻辑删除（不再物理删除）

- **改法**：`model.EzfyOfficer` 加 `DeletedAt gorm.DeletedAt`。
  `Delete` 变成 `UPDATE ... SET deleted_at=NOW()`；所有 `Find/First/Count` 自动带
  `deleted_at IS NULL`；看已删行用 `.Unscoped()`。
- **还原一行**：`UPDATE ezfy_officer SET deleted_at = NULL WHERE id = ?`
- ⚠️ **硬依赖列**：列不存在 → GORM 给所有军官查询加的条件全部报错 → **军官模块全挂**。
  所以 `EnsureEzfyOfficerColumns` 幂等补列 + 补索引，失败打 `【严重】` 日志；
  线上库**已预先补好这一列**（第三节）。
- ⚠️ 原生 `Table("ezfy_officer o")` 查询不会自动带软删除条件 →
  已给管理端「名将拥有者」列表手写 `o.deleted_at IS NULL`。

### ③ 修「战俘不能释放」

- **问题**：`freeOfficer` / `recruitCaptive` 用 `officerOf(当前城.ID, id)` 找军官，
  当前城与军官所在城不一致时（前端切城、列表刷新与点击之间切城）直接返回 nil →
  报「武将不存在」，按钮点了没反应。
- **改法**：新增 `officerOfMine(uid, id)`，按**玩家名下所有城**找，并返回军官真实所在城。

### ④ ★ 参谋部容量 与 战俘营容量 **分开算**（两套）

| | 容量公式 | 占用数 | 用在哪 |
|---|---|---|---|
| **参谋部容量**（在职军官位） | **参谋部等级** | `officerCount`（只数在职，不含俘虏） | 军校招募、收编俘虏 |
| **战俘营容量** | **当前城参谋部等级 × 4** | `captiveCount`（只数俘虏） | 野地/寇城/活动野地收押、PvP 抢将 |

- 新增 `ezfyCaptivePerStaff = 4`；`h.officerCapacity(cityId)` = 参谋部等级，
  `h.captiveCapacity(cityId)` = 参谋部等级 × 4；占用数新增 `captiveCount` / `captiveCountOf`。
- `/officers` 下发字段拆开：`capacity`（军官位=等级）、`used`（在职数）、
  `captive_capacity`（=等级×4）、`captive_used`（俘虏数）。
- 军校招募页 `AcadeRecruit` 的 `capacity` 也回到「参谋部等级」。
- 提示文案同步：军官位满时报「参谋部容量不足(参谋部9级容纳9名军官)」。

### ⑤ ★ 战俘营**按城市分**（绑在玩家城市上）

- `/officers` 的 `captives` **只返回当前城的俘虏**；容量也只看当前城参谋部等级。
  **2026-09-29 那版「跨城汇总」已取消。**
- 实现上直接从当前城军官列表 `list` 内存筛出俘虏 → 比原来还**少一条 SQL**。
- ⚠️ **玩家可见变化**：俘虏落在「出征发兵的那座城」，多城玩家要看某座城的俘虏，
  得先**切到那座城**（不再全服汇总显示）。如果之后觉得不方便，可以再加一个
  「其他城的俘虏」只读列表 —— 跟我说一声就行。
- 前端同步：战俘营页头改成 `战俘营(已用/容量)`，并加了一行「按城市分」的说明；
  `officerData` 默认值补了 `captive_capacity` / `captive_used`。

```sql

ALTER TABLE ezfy_officer ADD KEY idx_ezfy_officer_deleted_at (deleted_at);
```
- 复核：`deleted_at` 列存在、索引存在、`deleted_at IS NOT NULL` 的行数 = **0**。

- 旧二进制不认识这一列，不受影响（可随时 `DROP COLUMN` 回滚）。

## 五、部署注意

1. **直接发新二进制即可**：新代码启动时会先跑 `EnsureEzfyOfficerColumns` 再起路由，
   就算线上没预先补列也会自己补上。
2. **不要只发二进制却把补列那段注释掉** —— `deleted_at` 是硬依赖，缺列 = 军官模块全挂。
3. 发版后建议冒烟：`/officers` 能出列表、招募一次、战俘营释放一个（挑当前城的俘虏）。
