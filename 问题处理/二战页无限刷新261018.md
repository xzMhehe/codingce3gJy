# 二战页「无限刷新 / 地址栏狂拼 `/:8081`」修复 —— 2026-10-18

> 现象（用户报告）：
> 1. `http://124.222.208.92:8080/#/games/ezfy?cur=home` 会**无限刷新**；
> 2. 地址栏变成 `http://124.222.208.92:8080/:8081/:8081/:8081/...（16 层）/#/games/ezfy?sso_token=eyJ...`。
>
> 结论：**不是后端问题，是家园 SPA 路由守卫把区服相对地址 `:8081` 当 URL 直接跳，浏览器按相对路径反复拼接。**
> 已修复，dist 已重建，**待部署**（线上实测仍是旧包，见下）。

---

## 一、根因

### 1.1 背景

`game_servers.host` 支持 `:8081` 相对写法（2026-10-18 上午上的功能：多机共享同一个家园库时，谁访问就跳谁自己的机器）。**后端** `router.go::ezfyZoneURL` 正确解析了（`/api/ezfy/zone` 实测返回的就是原始写法 `":8081"`，由前端负责解析）。

### 1.2 出事的代码

家园 SPA 的路由守卫 `web/src/router/index.js::beforeEach`（2026-10-17 二战独立部署时加的）里，**自己又写了一份区服跳转**，没有做 `:端口` 解析：

```js
api.get('/ezfy/zone').then(r => {
  const zone = list.find(z => z && z.host) || null
  ...
  window.location.href = zone.host.replace(/\/+$/, '') + '/#' + p   // ← zone.host = ':8081'
})
```

### 1.3 死循环是怎么转起来的

1. 玩家访问 `http://124.222.208.92:8080/#/games/ezfy?cur=home`
2. 守卫拿到 `zone.host = ':8081'` → `location.href = ':8081/#/games/ezfy?sso_token=...'`
3. 浏览器把 `:8081/...` 当**相对路径** → 解析成 `http://124.222.208.92:8080/:8081/#/games/ezfy?sso_token=...`
4. 8080 是 SPA fallback（任何 path 都吐 index.html）→ 页面再次加载 → hash 还是 `/games/ezfy` → **守卫再跳一次**
5. 这次当前目录是 `/:8081/` → 拼成 `/:8081/:8081/` → 每转一圈多一层 → **无限累加 + 无限刷新**

### 1.4 为什么 Games.vue 里的入口没问题

`Games.vue::enterServer` 有一份 10-18 加的 `resolveSrvHost()`，能正确把 `:8081` 解析成 `http://<当前域名>:8081`。**两处各写一套，守卫那处没同步** —— 正是「规则只有一处实现」教训的重演。

### 1.5 线上实证

抓线上 `chunk-common.7892bb14.js`，守卫代码原样躺着未修复：

```js
window.location.href = o.host.replace(/\/+$/, "") + "/#" + m
```

且整个 bundle 里 `resolveZoneHost` / `resolveSrvHost` 出现次数 = **0**（线上是旧 dist，连 Games.vue 的解析都没部署过）。

## 二、修复（代码已改，dist 已重建）

### 2.1 唯一实现：新增 `web/src/utils/zoneHost.js`

| 导出 | 作用 |
|---|---|
| `resolveZoneHost(raw)` | 把 host 三种写法解析成绝对地址：`''`→本服同源、`:8082`/`//:8082`→当前域名+端口、`http(s)://`→原样；裸 `host:port` 也兜了 |
| `isAbsoluteHttpUrl(u)` | **护栏**：只有绝对 http(s) 地址才允许 `location.href` 整页跳 |
| `looksLikeBrokenZonePath(pathname)` | 检测 `/:8081/:8081/...` 坏形态，命中就回首页，**绝不再跳** |

### 2.2 三个跳转点全部接入（同一套护栏）

| 文件 | 位置 | 改动 |
|---|---|---|
| `web/src/router/index.js` | `beforeEach` 的 `to.meta.ezfy` 分支（**事故源头**） | `resolveZoneHost(zone.host)` 解析；非绝对地址 → `next('/')` 兜底；地址栏已坏 → `location.replace('/')` 回首页 |
| `web/src/views/Games.vue` | `enterServer` | 删掉内联 `resolveSrvHost`，改 import 公共实现 + 同款护栏 |
| `web/src/views/ezfy/Ezfy.vue` | `exitToHome` | `homeUrl` 必须是绝对 http(s) 才整页跳（防 config 里把 `home_url` 配成 `:8080` 也触发同类死循环）；坏形态兜底 |

### 2.3 护栏测试（新增 `server/internal/handler/ezfy/ezfy_zone_host_guard_test.go`）

静态断言前端源码，防「一处修了另一处没修」复发：

- `TestZoneHostSingleImplementation` —— `utils/zoneHost.js` 是唯一实现，Games.vue 禁止再有内联解析
- `TestZoneJumpersAllGuarded` —— 三个跳转点必须引入 zoneHost、调用解析 + `isAbsoluteHttpUrl` + `looksLikeBrokenZonePath`
- `TestRouterGuardNeverHrefsRelativeAddress` —— 守卫禁止 `location.href = zone.host...` 原样拼接
