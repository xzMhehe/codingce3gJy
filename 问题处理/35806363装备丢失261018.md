## 三、根因（代码）

### 3.1 出事的地方

`server/internal/handler/ezfy/ezfy_chat_exchange.go:1513`

```go
// deleteCityData 删除城市及其所有数据
func (h *EzfyHandler) deleteCityData(cityId int64) {
	h.DB.Where("city_id = ?", cityId).Delete(&model.EzfyCityBuilding{})
	...
	// ★ 2026-09-24：占城摧毁后军官/装备一并清理（对齐 ezfyDestroyCity，不留孤儿数据）
	h.DB.Where("city_id = ?", cityId).Delete(&model.EzfyOfficer{})
	h.DB.Where("city_id = ?", cityId).Delete(&model.EzfyEquipment{})   // ← 元凶
	h.DB.Delete(&model.EzfyCity{}, cityId)
}
```

调用点：`ezfy_chat_exchange.go:1250`，即 `OccupyOp` 的 `destroy` 分支（占领别人的城之后点「摧毁」）。

### 3.2 这是 2026-10-13 那次事故的同款 bug，只修了一半

`ezfy.go:4786` 已经写得很清楚（10-13 线上用户 35806411 一次丢 305 件）：

> 装备的归属是 **user_id**（`equipmentList(uid)` 就是 `WHERE user_id = ?` 全局查，界面不分城），
> `city_id` 只是**获得时的出生城**、而且穿戴/转移到别城军官后**不会更新**。
> 拿 `city_id` 当删除依据 = 把「出生地」当「存放地」。

当时的修复只改了 `ezfyDestroyCity`（拆自己的城）：

```go
h.DB.Model(&model.EzfyEquipment{}).Where("city_id = ?", cid).
	Updates(map[string]interface{}{"officer_id": 0, "city_id": mainId})
```

**`deleteCityData`（占城摧毁，别人的城）这条路径漏改了**，护栏 `ezfy_city_destroy_equip_test.go` 也只断言了 `ezfyDestroyCity` 里没有 `Delete(&model.EzfyEquipment{})`，所以 CI 全绿。

玩家的青天白日分五批从五个号俘虏过来，`city_id` 分别落在 40 / 36 / 38 / 39 / 55 / 152 / 59：

### 5.1 代码（初版方案，已被第七节取代）

`deleteCityData` 里**不再按 city_id 物理删装备**，改成「卸下 + 按 owner 迁回各自主城」：

```go
// ★★ 2026-10-18 修复「占城摧毁把账号装备一起删了」（35806363 丢三件青天白日）：
//   装备归属是 user_id，city_id 只是出生城（俘虏/派遣后不更新）
//   → 不能按 city_id 物理删；按 owner 分组，各自迁到 id 最小的另一座城。
var owners []uint
h.DB.Model(&model.EzfyEquipment{}).Where("city_id = ?", cityId).Distinct().Pluck("user_id", &owners)
for _, owner := range owners {
	var mc model.EzfyCity
	mainId := int64(0)
	if err := h.DB.Where("user_id = ? AND id <> ?", owner, cityId).
		Order("id ASC").First(&mc).Error; err == nil {
		mainId = int64(mc.ID)
	}
	h.DB.Model(&model.EzfyEquipment{}).Where("city_id = ? AND user_id = ?", cityId, owner).
		Updates(map[string]interface{}{"officer_id": 0, "city_id": mainId})
}
h.DB.Where("city_id = ?", cityId).Delete(&model.EzfyOfficer{})
```

要点：
- **顺序**：先迁装备，再删军官（删军官不影响装备行，但语义上先保住资产）。
- `mainId = 0` 时（owner 只有这一座城）→ city_id 置 0，装备仍按 user_id 在账号背包里，不会丢。
- 加护栏：`ezfy_city_destroy_equip_test.go` 增加对 `deleteCityData` 的断言（禁止 `Delete(&model.EzfyEquipment{})`、必须有按 owner 迁城的 Updates）。

## 七、装备与城市**彻底解耦**（2026-10-18 13:15，代码已改，待部署）

> 用户定调：「装备不是跟城市的，弃城装备应该在军官身上或者在背包里，装备和玩家背包关联，现在有大雷。」

### 7.1 定案：装备只认两个外键

| 外键 | 含义 |
|---|---|
| `user_id` | 属于哪个账号（唯一的归属依据） |
| `officer_id` | 穿在哪名军官身上；`0` = 在背包里 |

`ezfy_equipment.city_id` **彻底废弃**（恒 0）。它是历史「获得时的出生城」，穿戴 / 俘虏转移 / 派遣到别城之后都不更新，是两次事故的共同根源：

- 2026-10-13 弃城：`DELETE ... WHERE city_id = ?` → 丢 305 件（35806411）
- 2026-10-18 占城摧毁：`DELETE ... WHERE city_id = ?` → 丢 3 件青天白日（35806363）

### 7.2 代码改动

| 文件 | 改动 |
|---|---|
| `internal/model/ezfy.go` | `EzfyEquipment.CityId` 注释改为「已废弃（历史出生城，恒0）；装备归属只看 user_id，禁止按它删除/迁移」 |
| `internal/handler/ezfy/ezfy_officer.go` | `buildEquipment` **不再写 `CityId`** → 新装备恒 0 |
| `internal/handler/ezfy/ezfy.go` | `ezfyDestroyCity`（弃城）删掉「按 city_id 迁主城」，改成**按军官解绑**，并移到删军官之前 |
| `internal/handler/ezfy/ezfy_chat_exchange.go` | `deleteCityData`（占城摧毁）删掉 `Delete(&model.EzfyEquipment{})`，同样按军官解绑 |
| `internal/seed/ezfy_equipment_nocity.go` | **新增** `EnsureEzfyEquipmentNoCity`：`UPDATE ... SET city_id=0 WHERE city_id<>0`（幂等，只改一个无人读取的字段） |
