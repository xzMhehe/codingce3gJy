## 三、概率复核：60 连不出套装是正常结果

### 3.1 当前奖池权重（`ezfy_cfg_chest_item`）

**帝国宝箱（chest 3）**

| 类型 | 权重合计 |
|---|---|
| 道具（4 行） | 40 + 20 + 30 + 40 = 130 |
| 套装（3 行：海军上将/传说英雄/名门征服） | 1 + 1 + 1 = 3 |
| 合计 | 133 |

单抽出套装概率：`3 / 133 = 2.26%`
30 连一件套装都不出的概率：`(130/133)^30 ≈ 50.4%`

**战神宝箱（chest 4）**

| 类型 | 权重合计 |
|---|---|
| 道具（3 行 + 11 行 ×100） | 40 + 40 + 10 + 1100 = 1190 |
| 套装（2 行：传说无畏/传说征服） | 2 + 2 = 4 |
| 合计 | 1194 |

单抽出套装概率：`4 / 1194 = 0.335%`
30 连一件套装都不出的概率：`(1190/1194)^30 ≈ 90.4%`

**两箱合计 0 套装概率：`50.4% × 90.4% ≈ 45.6%`。**

也就是说，这次结果接近“抛硬币”，并不是小概率异常，更不是数据丢失。

## 四、根因与问题定性

### 4.1 直接原因

**没有装备丢失。** 15:12:30 / 15:12:44 两次开箱的 60 次抽取都没有命中套装奖池；
两次开箱只发放了道具，装备表没有新增、也没有删除。

### 4.2 玩家为什么会产生“丢了”的错觉

1. **切城后看不到军官**：9 件套穿在 74 城的军官 280 身上，玩家当前在 82 城，
   军官列表按城过滤，装备看起来“消失”了。
2. **宝箱描述像“必出整套”**：
   - 帝国宝箱：`des = "开出一整套中级套装（9 件）"`
   - 战神宝箱：`des = "开出一整套高级套装（9 件）"`
   但实际套装概率只有 **2.26% / 0.335%**，玩家开了 30 个还没出，自然认为被吞了。
3. **管理端开箱流水被截断**：战神宝箱 30 连只显示 24 条，最后 6 条看不到，
   进一步加深“东西少了”的怀疑。

### 4.3 次要问题（建议修，但不是本次丢装备的原因）

1. `ezfy_chest_logs.result` 只有 `varchar(255)`，30 连必截断。
2. 宝箱 `des` 文案与真实概率不一致。
3. 军官列表按城过滤，但界面没有提示“该军官在其它城”，跨城后容易误判装备丢失。

## 五、处理建议

### 5.1 对玩家的解释口径

> 你 15:12 开的 30 个战神宝箱 + 30 个帝国宝箱，开出的都是道具，没有抽到套装；
> 你身上的「遗失传说」9 件套还在军官「尼米兹」身上，该军官在 74 城。
> 你当前在 82 城，军官列表只显示本城军官，切回 74 城就能看到。
> 两个宝箱的套装概率分别是 2.26% 和 0.335%，60 连不出套装约 45.6% 概率，属于正常结果。

### 5.2 代码/配置建议

1. **开箱流水扩容（已于 2026-10-21 修复）**
   - `ezfy_chest_logs.result`：`varchar(255)` → `text`；
   - `ezfy_diamond_logs.extra`：`varchar(255)` → `text`；
   - 去掉 `ChestBagOpen` / `ChestOpen` 里的 255 字符截断；
   - 同名奖品聚合逻辑同步修正，不再出现 `荣誉史记×1×11、荣誉史记×1…` 这种膨胀文本；
   - `EnsureEzfyChestLogTable` 改为每次都执行 `AutoMigrate`，skip 分支也会把存量列扩到位；
     另加 `EnsureEzfyDiamondLogColumns` 处理钻石流水 `extra`。
   - 注意：历史记录（如 ID 41）只有当时写入的 255 字符，**无法恢复**被截掉的后 6 条；
     部署后新开的宝箱才会完整记录。
   - 如需立即生效，可手工执行（新二进制启动时也会自动迁移）：

     ```sql
     ALTER TABLE ezfy_chest_logs
       MODIFY COLUMN result text COMMENT '开出的东西(聚合文本，完整不截断)';
     ALTER TABLE ezfy_diamond_logs
       MODIFY COLUMN extra text COMMENT '附加信息(宝箱开出的道具，完整不截断)';
     ```

2. **修正宝箱文案**
   - 把「开出一整套…（9 件）」改成「有概率开出…整套（9 件）」；
   - 或在宝箱详情里直接展示「套装概率 2.26% / 0.335%」。
3. **增加保底（可选）**
   - `ezfy_cfg_chest_item.min_draws` 目前所有套装行都是 `1`（不启用）；
   - 可给套装行设置保底，例如帝国 50 次、战神 100 次内必出一次整套，
     避免“开了几十个什么都没出”的体感。
4. **跨城提示（可选）**
   - 军官列表为空/少时，提示「你有 N 名军官在其它城市」；
   - 或在装备页按 `user_id` 展示全部装备，不依赖当前城。

### 5.3 如果玩家仍坚持“具体某件装备丢了”

当前证据只能证明 **15:12 两次开箱没有产生/删除装备**。
如果玩家能提供具体的装备名称、部位、获得时间或截图，可以再按以下路径核查：

1. 查 `ezfy_equipment` 是否还在（按 `user_id + name/cfg_id`）；
2. 查是否被以下正常消耗逻辑删除：
   - 军衔晋升扣宝物（`ezfy_rank_treasure.go`）
   - 宝物赏赐军官（`ezfy_officer.go`）
   - 宝物出售（`ezfy_chat_exchange.go`）
3. 必要时用 RDS binlog（`log_bin=ON`）按时间点回放 `ezfy_equipment` 的 DELETE/UPDATE；
4. 对比 RDS 自动备份。
