# 家园社区(QQ家园复刻版)—— 项目背景

## 一、项目缘起

腾讯 QQ家园(又称「家园社区」)是 2008 年上线的一款移动端社区产品,当年凭借「3GQQ 家园」入口风靡一时,承载了整整一代人**签到、盖楼灌水、聊天交友、玩小游戏**的青春记忆。2015 年 6 月 20 日,QQ家园正式停止运营,无数用户的「家园号码」、帖子、好友关系随之湮没在互联网的角落。

本项目是一次**情怀驱动的完整复刻**:用现代技术栈把 QQ家园的核心形态重新搭起来,让当年那些功能和页面气质得以延续。

## 二、参考来源:家园演示源码(历史遗留代码)

项目根目录下的 `家园演示源码/` 是重要的历史参考资料,主要内容包括:

| 内容 | 说明 |
|------|------|
| `yanshi.com/` | 当年家园演示站留存下来的**大量静态 HTML 页面**(约千余个),包含:广场首页(`index*.html`)、论坛(`forum.html`、`topic*.html`、`show.html`)、登录注册(`login*.html`、`reg.html`)、用户主页(以家园号码命名的页面,如 `35797804.html`)、游戏入口(`enter_game.html`)、分享页、公告页等 |
| `static/` | 演示站的静态资源(样式、图片、动画素材等) |
| `家园功能参考/` | 功能参考目录(目前为空,待补充) |

这些历史遗留代码是复刻的**「第一手资料」**:页面结构、栏目划分、文案风格、用户数据形态(如家园号码规则、等级体系、马甲/勋章样式)均从中提炼,再结合现代工程重新实现。

## 三、技术选型

- **后端**:Go 1.26 + Gin + GORM,MySQL 8 存储,Redis 不在依赖范围内(当前为直连 MySQL 的轻量实现)
- **前端**:Vue 2.7(vue-router + vuex + axios),Element UI(管理端),复刻演示站 WAP 风格样式
- **架构**:前后端分离;RBAC 权限模型(用户-角色-权限三级)
- **部署形态**:后端生产模式可直接托管两个前端构建产物(web/dist、admin-web/dist),一条命令启动整个系统

## 四、系统架构

```
qqjiayuan/
├── server/          # Go 后端(Gin + GORM + JWT + RBAC),端口 8080
│   ├── config.yaml  # 端口 / MySQL / JWT 配置
│   ├── internal/    # config / model / middleware / handler / router / seed
│   └── pkg/         # 数据库初始化、JWT 工具、统一响应
├── web/             # 用户端前端(Vue 2.7),开发端口 8000,生产由后端托管
├── admin-web/       # 管理端前端(Vue 2.7 + Element UI),路径 /admin-ui/,开发端口 8001
└── games/           # 游戏相关(大厅入口已预留,小游戏暂未开发)
```

三个子系统可独立开发调试(前端 dev server 将 `/api` 代理到后端 8080),也可整体构建后由后端统一托管。

> **开发模式与生产模式的端口说明**
> - 开发时务必用前端 dev server(热更新),不要用后端起服务:
>   - 用户端 `web` → `npm run serve` → **http://localhost:8000**
>   - 管理端 `admin-web` → `npm run serve` → **http://localhost:8001/admin-ui/**
>   - 两个前端端口**不同**(用户端 8000、管理端 8001),避免冲突。
> - 生产时由后端统一托管构建产物(`web/dist` 与 `admin-web/dist`),`start.bat` 一键构建 + 启动,访问 `http://127.0.0.1:8080` 与 `/admin-ui/`。

## 五、核心功能

### 用户端
- 用户系统:注册自动分配家园号码(靓号)、登录(号码/昵称)、找回资料、修改资料/密码、头像、昵称颜色
- 社区广场:公告/广播/活动、在线人数、最新居民、社区头条(精华)、频道最新帖、友友动态、社区搜索
- 论坛盖楼:分区-板块两级、发帖、回复盖楼(自动楼层)、浏览/回复计数、置顶/精华、分页
- 每日签到:连续签到奖励递增、连续天数榜、全站签到统计
- 社交:好友(按号码添加/申请/同意)、私信(会话列表/未读/已读回执)、聊天室(全园公共聊天,轮询刷新)、消息通知
- 等级经验:发帖/回帖/签到获得经验金币,等级称号(新人报到→…→一代宗师)
- 马甲/勋章:昵称前图标串、等级图标自动生成,素材还原自演示站原版

### 管理端(独立系统 admin-web)
- 社区概览统计、用户管理(封禁/重置密码/分配角色/设马甲)、板块管理、帖子管理(置顶/精华/删帖)、公告管理(公告/广播/活动)、角色权限管理(自建角色、勾选权限)、马甲管理
- 权限按角色显示:超级管理员 / 管理员 / 版主 可见范围不同

### 游戏(规划中)
抢车位、好友买卖、魔法花园、阳光牧场、精武堂、召唤之王、纵横四海等经典小游戏——游戏大厅入口已预留,暂时不做,先把家园社区本体搭起来。

> **二战风云(ezfy) 已复刻上线**(2026-09):参照 gitee stzb-fk 项目 `feature-ezfy-ai` 分支的 Java 源码,在 Go 后端完整复刻核心玩法——城池建造、资源懒结算、造兵科技、伤兵逃兵、世界地图(哈希生成野地/海野/寇城)、七类出征(侦查/掠夺/征服/采集/运输/增援/派遣)、多回合战斗引擎(逐回合战报)、宣战/占领(建立城市/摧毁/归还)、军团(成员/聊天/踢人)、世界聊天、交易所(挂单买卖资源)、商城背包、任务、签到福利、军衔声望排行、统帅信息。页面完整复刻原版 WAP 文字风格(深蓝标题栏/纯文字行/小图标),与家园页面一致靠左排布。数据表全部使用 `ezfy_` 前缀(34 张,配置数据源自 inithebing.sql 转换)。入口:游戏大厅「二战风云」→ `/games/ezfy`,账号即家园账号。管理端已配玩家/数据/流水/系统四组管理接口。军官系统(军校/技能/装备)为待扩展项。

## 九、开发约定（勿违）—— 所有 AI 助手必读

> 这几条是用户明确要求过的铁律。动手写代码/文案之前先看这一节，别重复踩。

### 1. 界面上**不要**写解释性提示文案

用户原话：「尽量不要在用户前端加提示，写到代码里面就行了」「管理系统好多提示。。。。。我都无语了」。

- **禁止**在用户端（`web/`）和管理端（`admin-web/`）界面上添加**说明性/解释性**文字：
  玩法说明、规则解释、给玩家的提示语、给管理员的操作指引、设计口径的科普。
- 这类信息一律写进**代码注释**（Go / Vue 都可以），或写进本文件 / `.workbuddy-ai/memory/`。
- 只允许保留**功能性文字**：按钮与链接文案、字段名与表头、数值与单位、
  校验失败与操作结果的即时反馈（如「钻石不足」「已下达指令」）、空列表占位（一句话以内）。
- 判断标准：**原版游戏/原版后台界面上不会出现的东西，就不要写上去。**

### 2. 服务器是 1 核 1G，性能红线不能踩

- `calcResource()` 里禁止查库（它是所有接口的必经懒结算）。
- `refreshCity` / `processOrders` / `processArrive` 之间禁止无守卫互调（天然环）。
- 禁止在请求路径上做全图枚举；**禁止 N+1 查询**（循环里查库）。
- 详细踩坑记录见 `.workbuddy-ai/memory/MEMORY.md` 的「性能红线」一节。

### 3. 复刻类页面不要自作主张加装饰

- 不要加 `WAP报时:`、`联系我们：`、`<hr/>` 下划线这类原版没有的元素。
- 字号/布局以现有基准为准，**不要擅自改**（历史上三轮改字号全被否决）。
