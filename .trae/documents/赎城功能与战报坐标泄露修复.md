# 赎城功能 + 战报坐标泄露修复

## Context（背景）

用户在测试中被攻破城市（被打飞），发现两个问题：

1. **坐标泄露**：攻方「征服报告」正文把守方补给新城市的坐标直接写了出来（[ezfy_order.go:3474](file:///Users/mxz/mxz-code/github/codingce3gJy/qqjiayuan/server/internal/handler/ezfy/ezfy_order.go#L3474) `守方城市已全部被占, 系统已补给新城市[%s](%d,%d)`），攻击者拿到坐标可以继续追打。预期：攻方战报**不出现新坐标**；守方自己的「系统补偿新城市」报告保留坐标。

2. **赎城需求**：自己的城市被占领（`ezfy_occupy` status=1，城市行 user_id 仍属原主人）后，城市列表仍显示 [运输][派遣][弃城] 三个按钮。预期改为显示 **[赎城]**：原主人花 N 钻石（管理端可配，默认 500）发起赎回，攻击者同意后钻石归攻击者、城市返还；拒绝/撤销则押金退回。

用户已确认的关键决策：
- 支付时机：**发起即扣**（检查余额 ≥ 金额），拒绝/撤销自动退回；同意后金额转给攻击者
- 金额：**管理端可配**（`ezfy_cfg_limit` 加列 `ransom_cost`，默认 500）
- 范围：**仅「占领中」（occupy status=1）可赎**；已被攻击者「建立城市」（过户 status=4）或「摧毁」的不可赎

## 实施方案

### 一、坐标泄露修复（后端，纯改动）

`ezfy_order.go` L3474：攻方战报去掉新坐标：

```go
report += fmt.Sprintf("\n守方城市已全部被占, 系统已补给新城市[%s]", newCity.Name)
```

守方自己的报告（L3475-3476）保持带坐标不变。

### 二、赎城功能（后端）

**1. 新增表 + 模型**（`server/internal/model/ezfy.go`）

```go
// EzfyRansom 赎城请求：被占城市原主人发起，占领方同意后返还
type EzfyRansom struct {
    ID        uint   `gorm:"primaryKey" json:"id"`
    CityId    int64  `json:"city_id"`
    OccupyId  uint   `json:"occupy_id"` // 关联 ezfy_occupy.id
    DefUserId uint   `json:"def_user_id"`
    AtkUserId uint   `json:"atk_user_id"`
    CityName  string `json:"city_name"`
    X, Y      int    `json:"x" json:"y"`
    Cost      int64  `json:"cost"` // 发起时快照的金额（管理端可配）
    Status    int    `gorm:"default:0;comment:0待处理 1已同意返还 2已拒绝 3已撤销" json:"status"`
    CreatedAt, UpdatedAt time.Time
}
```

**2. 可配置金额**
- `model.EzfyCfgLimit` 加 `RansomCost int gorm:"default:500;comment:赎城金额(钻石)" json:"ransom_cost"`
- `ezfy_geo.go` 加 `ezfyRansomCost() int`：`ezfyCfg.limit.RansomCost > 0` 用之，否则 500
- `seed.go EnsureEzfyLimitColumns` 加幂等补列（照 drop_t2 模式）：`ransom_cost int DEFAULT 500` + `UPDATE ... WHERE IS NULL OR <= 0`
- `ezfy_admin_round9.go`：Get/List 两处默认值加 `RansomCost: 500`；Update 入参 struct 加 `RansomCost *int`，用 `setPos` 校验 ≥1，并加一条 `HasColumn("ransom_cost")` 防御补列

**3. 接口**（放 `ezfy_chat_exchange.go`，路由挂 `/games/ezfy/city` 组）

- `POST /city/ransom` `{city_id}` —— 原主人发起
  - 校验：城市存在且 `user_id == uid`；存在该城 status=1 的占领记录且 `def_user_id == uid`；该城无 status=0 待处理请求
  - cost := `ezfyRansomCost()`；`prof.Diamond >= cost` 否则提示不足；扣钻 + `logDiamond(uid, -cost, "赎城请求押金")`
  - 建 `EzfyRansom{Status:0, Cost:cost}`；通知攻击者：`addReport(atkUid, 5, "赎城请求", "原主人「%s」想花%d钻石赎回你占领的城市[%s](%d,%d)，可在[附属野地]的赎回请求中处理。")`
- `POST /city/ransom/handle` `{ransom_id, op}` —— 攻击者（`atk_user_id == uid`）处理，op: 1同意 / 2拒绝
  - 请求必须 status=0；同意前**重校验**占领记录仍 status=1：
    - 已被建立/摧毁/归还（status≠1）→ 押金退回原主人、请求置 3，提示「该城市已被处理」
    - 同意：攻方 +cost 钻石 + `logDiamond(atk, +cost, "赎城收入")`；占领记录 status→2（同「放弃归还」口径：`user_id` 本就还是守方的，补 `feelings < 20 → 20`）；请求 status→1；通知双方
    - 拒绝：押金退回原主人 + `logDiamond(def, +cost, "赎城请求被拒退回")`；请求 status→2；通知原主人
- `POST /city/ransom/cancel` `{ransom_id}` —— 原主人（`def_user_id == uid`）撤销待处理请求：退押金 + `logDiamond(def, +cost, "赎城请求撤销退回")`；请求 status→3；通知攻击者
- `WildlandFull` 响应追加 `ransoms`：`atk_user_id == uid AND status = 0` 的请求列表（含原主人昵称、城市名、坐标、金额）

**4. /view 城市列表标记**（`ezfy.go`）
- `ezfyCityView` 加 `Occupied bool json:"occupied"`、`Ransoming bool json:"ransoming"`
- `cityViews` 里一次查询该批城市的占领/待赎状态（`SELECT city_id FROM ezfy_occupy WHERE status=1 AND city_id IN (...)`；`SELECT city_id FROM ezfy_ransom WHERE status=0 AND city_id IN (...)`）
- `viewPayload` 顶层加 `ransom_cost`（前端确认弹窗显示金额）

**5. 路由**（`router.go` city 组）：
```
ezfyG.POST("/city/ransom", ezfyH.RansomCreate)
ezfyG.POST("/city/ransom/handle", ezfyH.RansomHandle)
ezfyG.POST("/city/ransom/cancel", ezfyH.RansomCancel)
```

### 三、前端（web）

**1. 城市列表**（`EzfyCity.vue` L11-15）：被占城市不显示 [运输][派遣][弃城]，改为：
- `ct.occupied && !ct.ransoming` → `[赎城]`（点击调 `doRansom(ct)`，弹确认：花费 X 钻石，显示 `ezfy.ransomCost`）
- `ct.occupied && ct.ransoming` → `[撤赎城]`（点击调 `doRansomCancel(ct)`）
- 非被占城市照旧

**2. Ezfy.vue 方法**：
- `doRansom(ct)`：POST `/city/ransom` {city_id} → alert + 刷新
- `doRansomCancel(ct)`：POST `/city/ransom/cancel` {ransom_id} → 刷新
- `doRansomHandle(r, op)`：POST `/city/ransom/handle` {ransom_id, op} → 刷新
- state 加 `ransoms: []`、`ransomCost: 500`（wildfull/`/view` 下发时更新）

**3. 被占领城市面板**（`EzfyMap.vue` L624-640 下方）加「赎回请求」区块：
- 每行：原主人 / 城市(坐标) / 金额，按钮 `[同意][拒绝]`

**4. 管理端**（`AdminEzfyBuildLimit.vue`）加「赎城金额(钻石)」`el-input-number`（min=1），随现有 form 提交。

## 边界与约束

- 一座城同时最多 1 条待处理赎城请求（发起时校验）
- 处理/撤销均为幂等（status≠0 报「已处理」）
- 攻方「建立城市/摧毁/归还」与赎城并发时，以 handle 时占领记录状态为准（防脏数据）
- 钻石变动全部走 `logDiamond` 留流水
