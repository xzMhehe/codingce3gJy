# 二战征途「活动监测」管理端模块实施计划

## Context（背景）

近期活动频繁，运营需要管理端查看玩家活跃情况。新增「活动监测」模块，监测最近时间段内玩家的：**造兵次数、征服次数、掠夺次数、召集人口次数**。已与用户确认：征服/掠夺按「下单即算」（`ezfy_order`），页面为「汇总卡片 + 玩家排行表 + 时间范围选择（今日/近3天/近7天/自定义）」，召集人口新建埋点表（历史无数据）。核心约束：**性能**——聚合全部下推 SQL、复用/补建索引、避免 N+1。

## 步骤 3：接口 + 路由

新文件 `server\internal\handler\ezfy\ezfy_admin_monitor.go`，`func (h *EzfyAdmin) AdminEzfyMonitor(c *gin.Context)`：

**参数**：`start`/`end`（`yyyy-MM-dd` 或毫秒时间戳）、`page`/`size`（`pageOf(c,15)`）、`word`（账号/昵称）、`sort`（`train|conquer|raid|convene|total`，默认 `total` 降序）。

**流程**：
- 时间解析 helper `monitorRange`：end 取排他 `< end+1day`；都空默认今日。
- word 解析照抄 `AdminEzfyReports`（ezfy_admin.go L1036-1063）双库口径：纯数字=uid；非数字查 `ezfy_profile.nickname LIKE` + 家园库 `users.username LIKE` 合并 uid。
- 四条聚合 SQL（全部下推、GROUP BY user_id）：
  - 征服+掠夺一条：`Model(EzfyOrder{}).Select("user_id, order_type, COUNT(*) AS cnt").Where("order_type IN ?", []int{2,3}).Where("created_at >= ? AND created_at < ?", start, end).Group("user_id, order_type")`
  - 造兵一条：`Table("ezfy_train_queue t").Select("c.user_id AS user_id, COUNT(*) AS cnt").Joins("JOIN ezfy_city c ON c.id = t.city_id").Where("t.start_time >= ? AND t.start_time < ?", start.UnixMilli(), end.UnixMilli()).Group("c.user_id")`
  - 召集一条：`Model(EzfyConveneLog{}).Select("user_id, COUNT(*) AS cnt").Where(created_at 区间).Group("user_id")`
  - 均支持 `len(uids)>0` 时 `Where("user_id IN ?", uids)`
- 内存合并 `map[uint]*row{Train,Conquer,Raid,Convene,total}` → 按 sort 排序 → 切片分页。
- totals（全库窗口计数不分组）：train 用 JOIN COUNT、conquer/raid 各一条 `order_type=3/2` COUNT、convene 一条 COUNT。
- 名字补齐：`h.ezfyAdminNamesBatch(pageUids)`（ezfy_admin_wild.go L449，两条 SQL）。
- 返回：`{ totals:{train,conquer,raid,convene,players}, list:[{user_id, player_name, account, train, conquer, raid, convene, total}], page, size }`。

`router\router.go`：`ezfy-stats`（L1145）后追加：

```go
admin.GET("/ezfy-monitor", perm(db, "module:ezfySystem"), ezfyAdminH.AdminEzfyMonitor)
```

## 性能要点

- 聚合全部下推数据库（每条 GROUP BY SQL），内存只收每用户一行，杜绝捞全表。
- 新索引命中：`order_type IN (2,3) AND created_at`、`start_time` 窗口、`convene created_at`；全部 `ensureEzfyIndex` 幂等，存量库重启即补。
- 名字批量补齐（2 条 SQL），无 N+1。
- word 过滤进 SQL 先窄化。
- 已知近似口径：造兵按 `ezfy_train_queue` 行数 COUNT（"全部工厂"拆分模式一次点击计 n 次，轻度高估，无父单号可去重，接受）。
