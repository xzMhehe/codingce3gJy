# 二战风云「预设编队」功能实现方案

## Context（背景）

玩家在出征页（cur=orderpre）每次都要重新搭配 指挥军官 + 集结令 + 兵力，重复操作繁琐。需求：
1. **司令部**新增「预设编队」tab：可新增预设（镜像出征页 ①军官 ②集结令 ③兵力 + ⑥油耗计算预览）。
   - 预设**不包含** ④随军资源、⑤宿营（用户明确去除）；⑥油耗计算保留。
2. **出征页**在「指挥军官」上方加「预设编队」下拉，选中后回填出征内容：
   - 兵力不够 → 只填当前可出征上限（min(预设, orderQtyMax)）；
   - 军官不在当前城 → 回填空。
3. 数据存**后端数据库**（用户已确认，不用 localStorage）。

## 后端改动

### 1. 新模型 `EzfyPreset`（internal/model/ezfy.go，仿 EzfyMapStar L669-680）
表 `ezfy_preset`：
- ID uint primaryKey
- UserID uint `gorm:"index:idx_preset_user"`
- Name varchar(50)
- Officer varchar(255)（军官名，空=未指定）
- Gather int（集结令个数）
- Troops varchar(2000)（JSON `[{"troopId":1,"count":100}]`，与 EzfyOrder.Troops 同格式，可用现成 `parseGroups()`）
- CreatedAt

### 2. AutoMigrate 注册（internal/seed/seed.go）
在 L131 `&model.EzfyMapStar{},` 后加 `&model.EzfyPreset{},`。

### 3. 新 handler 文件 internal/handler/ezfy_preset.go（照抄 ezfy_star.go 模式）
- `Presets GET /games/ezfy/presets`：按 user_id 过滤倒序，用 `parseGroups` 还原 troops，每条附 `troop_total`（兵力摘要）。
- `PresetAdd POST /games/ezfy/presets` `{name, officer, gather, troops:[{troopId,count}]}`：
  - name trim 后 1~20 字；
  - troops 逐条校验：兵种存在且 type!=4（城防不可出征）、count≥1 且 ≤1e9、条数≤20、序列化≤2000 字符；
  - gather 夹 `[0, ezfyGatherMax()]`（ezfy_geo.go L559）；
  - officer 不校验存在性（回填时前端判断）；
  - 每 uid 最多 10 条（`const ezfyPresetMax = 10`），超了报「最多保存10个预设」；
  - `h.DB.Create(...)`。
- `PresetDelete POST /games/ezfy/presets/delete` `{id}`：按 `id AND user_id` 删。

### 4. 路由（internal/router/router.go，ezfyG 组 L577 后）
```go
ezfyG.GET("/presets", ezfyH.Presets)
ezfyG.POST("/presets", ezfyH.PresetAdd)
ezfyG.POST("/presets/delete", ezfyH.PresetDelete)
```
管理端、CreateOrder、OrderPreview **零改动**。

## 前端改动（web/src/views/Ezfy.vue）

### 1. 新增 data 字段（orderGather L4306 附近）
```js
presets: [],   // [{id,name,officer,gather,troops,troop_total}]
presetSel: 0,  // 出征页下拉选中 id (0=不使用)
presetName: '',// 新增预设名称输入
```
更新 L4187 注释：hqTab 4 = 预设编队。

### 2. 表单状态复用决策
复用共享的 `orderOfficer / orderGather / orderTroops / orderCalc`（cur=hq 与 cur=orderpre 互斥，orderpre 进场 resetOrderForm 清空，无串数据）。**不复制独立字段**。新增 `presetCalc()`（预设页计算，传 target=本城坐标 0 距离估算，order_type=2，不走现成 doCalc——它依赖 selCell）。灰字提示「预设不含目标，油耗按本城0距离估算，实际以出征页计算为准」。

### 3. 司令部「预设编队」tab（hqTab===4）
- acade-tab（L886-891）加 `<a :class="{on:hqTab===4}" @click="selectHqTab(4)">预设编队({{presets.length}})</a>`。
- 逃兵营 tab 后（L978）插入面板：
  - **新增表单**：名称 input（maxlength 20）+ ①军官 select（onDutyOfficers，v-model=orderOfficer）+ ②集结令（v-model=orderGather，max=gatherMax，@change=onPresetGatherChange）+ ③兵力滑块行（原样复制 L1443-1461，复用 orderQtyMax/orderQty/onOrderQtyInput/setOrderQtyMax）+ ⑥预览（[计算] 按钮 → presetCalc，显示 oil_used/carry/troop_cap，不显示耗时）+ `[保存预设]`。
  - **预设列表**：table（名称 / 军官 p.officer||'无' / 兵力 fmtN(p.troop_total) / 集结令 / [删除]）。
- selectHqTab(v) L6006：`if (v===4){ this.loadPresets(); this.$nextTick(()=>this.presetCalc()) }`。

### 4. 出征页预设下拉 + 回填
- L1397 ①军官之前插入「预设编队」select（`v-model="presetSel"`，`:value="0"` 空选项 + 各预设，另加 `[管理预设]` 链接跳 hq tab4）。
- `applyPreset()`：
  - 军官：名字不在 onDutyOfficers → `orderOfficer='0'`；
  - 兵力：清空 orderTroops 后逐条 `$set(orderTroops, troopId, min(preset, orderQtyMax(id)))`；
  - 集结令：`min(preset.gather, gatherMax)`；
  - 最后 `doCalc()`（真实目标重算 + clampOrderTroops 夹回上限）。

### 5. 新增/修改函数清单
| 位置 | 改动 |
|---|---|
| `loadPresets()` 新增 | GET /games/ezfy/presets |
| `presetCalc()` 新增 | target=本城坐标估算，写 orderCalc + clampOrderTroops |

## 验证

1. 后端：`cd qqjiayuan/server && go build -o server.exe .`；停旧进程重启（8080），确认 ezfy_preset 表自动建。
2. 接口冒烟（登录 10000/admin123 → Bearer token）：
   - `GET /api/games/ezfy/presets` → presets:[]；
   - `POST /api/games/ezfy/presets` `{name:"掠夺主城", officer:"", gather:0, troops:[{troopId:1,count:100}]}` → code 0；GET 确认 troop_total；
   - 负例：空名称/21字、城防兵种 type=4、第 11 条（最多10个）；
   - `POST /api/games/ezfy/presets/delete {id:1}`。
3. 前端：`cd qqjiayuan/web && npm run build`（vue-cli 工程，产物 web/dist）。
4. 浏览器：司令部 tab4 新增/预览/列表/删除；地图点格子进出征页 → 选预设回填（军官缺失回空、兵力夹上限、集结令夹上限、自动重算）。

## 风险说明
- orderQtyMax 依赖 orderCalc（null 时退化为城内现有）→ applyPreset 先按城内现有夹，doCalc 返回后 clampOrderTroops 再按出征上限夹，最终正确。
- 预设页与出征页共享 orderType：若上次是运输/派遣，预设页滑块不按上限卡（仅显示层现象），保存/回填均正确，不为此复制字段。
- 下拉 value 用数字 id，空选项必须 `:value="0"`（数字，非字符串）。
- 后端修改后需重建重启；前端 build 后需部署 dist 并强刷（Ctrl+F5）。
