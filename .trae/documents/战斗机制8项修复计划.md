## 三、修复方案（逐项）

### 1. 科技/技能加成未算入伤害 —— 修复守方攻击无加成

**根因**：Step 里守方行动时 `unitAtkBonus = 0`（[ezfy_battle.go L407-413](file:///Users/mxz/mxz-code/github/codingce3gJy/qqjiayuan/server/internal/handler/ezfy/ezfy_battle.go)），城防/守城部队的攻击不吃科技+技能加成；守方在 processArrive 也只算了防御加成（L2557-2564）。

**改动**：
- `ezfyBattleState` 新增字段 `DefAtkBonus int`（守方攻击加成%）。
- `ezfyNewBattleState` 签名在 defBonus 后新增 `defAtkBonus int` 参数，存入 state。
- Step 守方行动分支：`unitAtkBonus = st.DefAtkBonus`（L407-413 处）。
- `ezfy_order.go` 守方块（L2557-2564 附近）：计算 `defAtkBonus = defTech[7]*3 + defTech[9]*2 + defTech[16]*2 + h.officerBattleBonus(cityGuard)`（装甲科技/重工技术/掩体防御/城守军官技能，与守方防御加成同口径）。
- 快照：`ezfyBattleSnapshot`/`ezfyBattleStateFromSnapshot` 增加 DefAtkBonus 往返（防止重建丢失）。
- 调用点同步加参数：processArrive 攻方块、[ezfy_activity_target.go L357](file:///Users/mxz/mxz-code/github/codingce3gJy/qqjiayuan/server/internal/handler/ezfy/ezfy_activity_target.go)（活动目标战斗同步修复）、ezfySimulate/ezfySimulateBreak 兼容包装传 0。

### 2. 射程 = 兵种基础射程 × (1 + 科技加成)

**根因**：引擎 `rangeD := unit.cfg.AttackRange`（[ezfy_battle.go L308](file:///Users/mxz/mxz-code/github/codingce3gJy/qqjiayuan/server/internal/handler/ezfy/ezfy_battle.go)）直接用基础值，无科技加成。科技表中「弹道学(8) 远程攻击+3%」最贴合射程语义。

**改动**：
- `ezfyBattleState` 新增 `AtkRangeBonus int`、`DefRangeBonus int`（射程加成%）。
- `ezfyNewBattleState` 签名新增 `atkRangeBonus, defRangeBonus int` 参数。
- Step 里 `rangeD := unit.cfg.AttackRange * (100 + 己方射程加成) / 100`（攻方用 AtkRangeBonus、守方用 DefRangeBonus），所有用到 rangeD 的地方（移动截断、开火判定、溢出射程过滤 L476-481）统一走这个有效射程。
- `ezfy_order.go` 攻方块：`atkRangeBonus = atkTech[8]*3`（弹道学）；守方块：`defRangeBonus = defTech[8]*3 + defTech[16]*2`（弹道学 + 掩体防御城防射程）。
- 快照增加两字段往返；simulate/simulateBreak 传 0。

### 3 + 4. 穿越 bug + 全部前进最终贴脸

**根因（合并处理，同一段移动逻辑）**：前进截断到「射程边缘」（L350-357），且 `dist > rangeD && nearestDist > rangeD` 才移动（L347）—— 双方都前进时各自停在射程边缘，既不贴脸又相互够不到；双方相向总移动量超过剩余距离时还会交叉穿越。

**目标语义（用户已确认）**：前进 = 冲锋到贴脸。沿途进入射程照常开火；到达贴身（距离≈0）后停下互射。hold 不动（射程内照常开火）；retreat 保留现后退逻辑。

**改动**（[ezfy_battle.go L331-395](file:///Users/mxz/mxz-code/github/codingce3gJy/qqjiayuan/server/internal/handler/ezfy/ezfy_battle.go)）：
- 前进（dir>0）不再受「dist > rangeD」限制：只要距离最近敌人 > 贴身间隔就移动。
- 移动量截断：`move = min(speed*(100+speedBonus)/100, 与最近敌人的当前距离 - 贴身间隔)`，贴身间隔 = 1（防交叉：逐个行动时后行动单位看到的是最新位置，截断到 `dist-1` 天然不穿越，最终所有前进单位汇聚贴身）。
- 保留「优先目标被挡、最近敌人在射程内 → 改打最近」（L392-395）与「够不到目标」静默日志（L383-389，仅在 hold/未移动且不在射程时输出）。
- 开火逻辑（L396+）不变：dist <= 有效射程即开火。
- 与 point2 结合：截断用的 rangeD 换成有效射程。

### 6. 保存/取消配置 + 伤害锁定机制

**语义（用户已确认）**：玩家设好兵种状态点「保存」→ 本回合该方配置锁定；锁定窗口内可「取消」重新配置；双方都保存 或 时间到 → 结算本回合并开新回合；时间剩余不多哪怕没操作完，按当前配置自动锁定（懒推进现有行为即满足）；攻守方皆可。

**后端改动**：
- 模型 [ezfy.go EzfyBattle](file:///Users/mxz/mxz-code/github/codingce3gJy/qqjiayuan/server/internal/model/ezfy.go)：加列 `AtkLock int`（攻方本回合是否已锁定）、`DefLock int`（守方），`default:0`（AutoMigrate 自动加）。
- 新接口 `BattleLock` POST `/games/ezfy/battle/lock` `{order_id, lock: bool}`（放 [ezfy_battle_room.go](file:///Users/mxz/mxz-code/github/codingce3gJy/qqjiayuan/server/internal/handler/ezfy/ezfy_battle_room.go)，路由在 user 端 games 组注册）：
  - 按 `ezfyBattleSide` 判定攻守，写对应 lock 字段（先写锁、后结算，同 BattleCmd 顺序）。
  - lock=true：置 1；若**双方都已锁**且本回合未结算 → 立即推进一回合：`RoundStart -= ezfyBattleRoundMs`（视为已到点），随后 `ezfyBattleTick` 自然补算，并清双方 lock（下回合重新可配）。
  - lock=false：仅当本回合尚未结算（`b.RoundStart + ezfyBattleRoundMs > now`）时置 0，允许重新下指令再保存；已到点结算后不可取消。
  - 返回 `ezfyBattleView` 全量状态。
- `ezfyBattleView`（L326-494）新增字段：`my_locked`（观察方自己是否已锁）、`atk_locked/def_locked`、`can_lock`（本回合指令期内）。phase 判定不变；「已锁定」时前端禁编辑。

**前端改动**：
- [EzfyMap.vue L384-389](file:///Users/mxz/mxz-code/github/codingce3gJy/qqjiayuan/web/src/views/ezfy/modules/EzfyMap.vue)：指令行上方/旁边加 `[保存配置][取消配置]` 链接；`my_locked=true` 时指令/目标下拉 disabled 并显示「已锁定」；取消后恢复可编辑。

   - 管理端：战报查询列表/详情/删除，按 word 与 report_type 过滤；
   - 对空/对地/对海：混合海陆空战斗的战报伤害与属性匹配。
4. 前端：`cd qqjiayuan/web && npm run build`、`cd qqjiayuan/admin-web && npm run build`。
5. 产物与部署：后端改动打包 `Linuxbushu.tar.gz + md5 + 部署命令` 交用户自行部署（用户偏好，不动服务器）；纯前端改动按用户流程重打包 web。
