# 家园 / 二战 统一入口方案

> 目标：玩家只记 **1 个 IP + 2 个端口**，二战不再暴露给玩家。
> 入口机：`47.102.48.155`（主） · 副机：`47.101.221.210`（可随时下线）
> 前提：两台机器**共用同一套 MySQL / 账号库**，`game_servers` 只有一份。

---

## 一、先说结论

| 玩家记什么 | 地址 |
|---|---|
| 主服 | `http://47.102.48.155:8080` |
| 副服（210，可能下线） | `http://47.102.48.155:8083` |

二战（1 区 / 2 区）**不用记**：在家园「游戏大厅」点「二战征途」自动整页跳转，
跳转地址由后端 `game_servers.host` 的 `:8081` / `:8082` 相对写法生成 —— 这条机制代码里已经有了
（`server/internal/router/router.go::ezfyZoneURL` + `web/src/utils/zoneHost.js`），不用改代码。

### 实测现状（2026-10-28 探测，可直接复用）

| 探测项 | 结果 |
|---|---|
| `155:8080/api/health` | 200，家园在跑 |
| `155:8081` `155:8082` | 200，二战 1 区 / 2 区都在跑 |
| `210:8080` `210:8081` `210:8082` | 200，三个都在跑 |
| `155:8080/api/ezfy/zone` | `[{host:":8081", 1区爽玩服}, {host:":8082", 2区诺曼底登陆}]` |
| `210:8080/api/ezfy/zone` | **与 155 完全一致** → 确认两台共用同一个 MySQL |
| 155 二战 `home_url` | `http://47.102.48.155:8080` ✅ 已对 |
| 210 二战 `home_url` | `http://47.101.221.210:8080` ← 建议改成 155 主入口 |

**结论：`game_servers.host` 已经是 `:8081` / `:8082` 相对写法，第 4.4 节不用做了。**
这意味着一装上 nginx、把 155 后端挪到 18080~18082，跳转逻辑自动就对 ——
玩家从 `155:8080` 进来 → `window.location.hostname` = `47.102.48.155` → 跳 `http://47.102.48.155:8081` → nginx → 18081。

## 三、端口规划

| 对外（155） | 转发到 | 服务 | 玩家可见 |
|---|---|---|---|
| 8080 | `127.0.0.1:18080` | 155 家园 | ✅ 主入口 |
| 8081 | `127.0.0.1:18081` | 155 二战 1 区 | 从家园自动跳 |
| 8082 | `127.0.0.1:18082` | 155 二战 2 区 | 从家园自动跳 |
| 8083 | `47.101.221.210:8080` | 210 家园 | ✅ 副入口 |
| 8084 | `47.101.221.210:8081` | 210 二战 1 区 | 仅容灾 / 管理端反代 |
| 8085 | `47.101.221.210:8082` | 210 二战 2 区 | 仅容灾 / 管理端反代 |

**为什么 155 的后端要挪到 18080~18082**：nginx 要占 8080/8081/8082，
而后端原来就绑在这三个端口上，不挪会抢端口起不来。18080 段只绑 `127.0.0.1`，公网碰不到。
210 的后端**不用挪**，保持 8080/8081/8082，由 155 的 nginx 反代过去。

## 四、要改的地方

### 4.1 · 155 三个 config.yaml：改端口

| 文件 | 改什么 |
|---|---|
| `/opt/Linuxbushu/server/config.yaml` | `server.port: 8080` → **`18080`** |
| `/opt/WWIIbushu/server/config.yaml` | `server.port: 8081` → **`18081`** |
| `/opt/wwii-2/server/config.yaml` | `server.port: 8082` → **`18082`** |

```bash
# 在 155 上执行（先确认路径和实际一致）
cd /opt/Linuxbushu/server && sed -i -E '/^server:/,/^[a-zA-Z_][a-zA-Z0-9_]*:/ s/^([[:space:]]*port:[[:space:]]*)[0-9]+/\118080/' config.yaml
cd /opt/WWIIbushu/server && sed -i -E '/^server:/,/^[a-zA-Z_][a-zA-Z0-9_]*:/ s/^([[:space:]]*port:[[:space:]]*)[0-9]+/\118081/' config.yaml
cd /opt/wwii-2/server   && sed -i -E '/^server:/,/^[a-zA-Z_][a-zA-Z0-9_]*:/ s/^([[:space:]]*port:[[:space:]]*)[0-9]+/\118082/' config.yaml

# 改完必须核对（三处都应是 1808x，mysql 的 3306 不能被动到）
grep -n -A3 '^server:' /opt/Linuxbushu/server/config.yaml
```

> `start.sh` 已经从 config.yaml 读端口做回显，不用改脚本。用 systemd 的话 `systemctl restart` 即可。

**155 二战 1 区 / 2 区的 `home_url` 也要改**（「返回家园」按钮）：

```yaml
server:
  home_url: "http://47.102.48.155:8080"
```

### 4.2 · 210 三个 config.yaml：关掉 bg_tick ★ 最重要

两台机器各跑 2 个区 = **4 个二战实例连 2 个库**。后台推进（战报结算 / 称号 / 人机）
如果两台都开，**同一批到点订单、到期建筑会被各结算一遍** —— 玩家白拿资源、战报重复。

```yaml
# /opt/WWIIbushu/server/config.yaml  和  /opt/wwii-2/server/config.yaml（210 机器）
server:
  bg_tick: false        # ★ 新增这一行，缺省不写 = true
  home_url: "http://47.102.48.155:8080"   # 返回家园回主入口
```

155 的二战两份配置**保持 true（或不写）**，全场只有 155 跑后台推进。

> 210 的二战 `bg_tick: false` 只关后台定时器，玩家读写、战斗、管理端接口全部正常 ——
> 因为它连的是同一个库，数据完全一致。

**容灾切主**（155 挂了，要让 210 接管）：把 210 两份配置改回 `bg_tick: true`，
同时把 155 两份改成 `false`（155 恢复后必须改回来），各自 `./stop.sh && ./start.sh`。

### 4.3 · 155 装 nginx

```bash
# 0) 先确认 8080~8085 没被别人占（155 上现在 8080/8081/8082 是三个后端，正常）
ss -lntp | grep -E ':(808[0-5])\b'

# 1) Alibaba Cloud Linux 3 / Anolis 8
dnf install -y nginx
systemctl enable --now nginx

# 2) 放配置（本仓库 nginx-gateway/qqjiayuan.conf）
cp qqjiayuan.conf /etc/nginx/conf.d/
nginx -t && systemctl reload nginx
```

配置见同目录 `qqjiayuan.conf`，6 个 server 块对应 6 个端口。

> ⚠️ 第 2 步会立刻报 `bind() to 0.0.0.0:8080 failed (Address already in use)` ——
> 因为 155 的家园后端还占着 8080。**先做第 1 步试水（只开 8083），
> 等第 2 步把后端挪到 18080~18082 之后，再把 8080/8081/8082 的 server 块放出来。**
> 顺序反了会直接起不来。

### 4.4 · game_servers 表：**已就绪，不用改**

实测已经是相对写法，改完 nginx 就能直接用：

```sql
-- 只想核对就跑这条
SELECT id, name, host, path, sort, status FROM game_servers ORDER BY sort;
-- 期望：host 分别是 ':8081' 和 ':8082'
```

如果哪天要手工改回来（比如回滚到直连）：

## 七、必须知道的坑

### 1. `bg_tick` 打架（第 4.2 节）—— 这是**现在就存在**的隐患

两台机器、4 个二战实例、2 个库。只要 210 的二战也开着 `bg_tick`，
到点订单 / 到期建筑就会被两边各结算一次。统一入口之前它就在发生，只是没人注意到。
**这一条比入口问题更该先修。**

### 2. nginx 的 Host 头必须带端口

后端 `ezfyZoneURL(":8081", scheme, c.Request.Host)` 靠 `Host` 里的 hostname 拼跳转地址。
如果 nginx 用默认的 `proxy_set_header Host $proxy_host`（= `127.0.0.1:18081`），
玩家点二战会被跳到 `http://127.0.0.1:8081` —— 直接挂。

所以每个 server 块里必须是：

```nginx
proxy_set_header Host $host:$server_port;
```

### 3. `proxy_redirect off;`

家园服（home 模式）有 `NoRoute` 302 跳二战，Location 是后端算好的绝对地址。
nginx 默认会尝试改写它，容易改坏。配置里已关。

### 4. jwt.secret 必须 6 个实例完全一致

2 个家园 + 4 个二战，`jwt.secret` 差一个字符，玩家从家园进二战就会被打回登录页。
改端口的时候顺手 `grep secret` 对一遍。

### 5. 210 的 8080/8081/8082 别急着对公网关死

玩家手里还有 `47.101.221.210:8080` 的旧书签。建议：
- 过渡期（1~2 周）210 的 8080 继续对公网开放
- 同时在游戏内 / 群里公告新地址
- 之后再收成「只允许 155 内网 IP 访问」

### 6. 安全组

| 机器 | 端口 | 授权对象 |
|---|---|---|
| 155 | 8080-8085 | `0.0.0.0/0` |
| 155 | 18080-18082 | **不开放**（只绑 127.0.0.1） |
| 155 | 3306 | 只允许 210 的内网 IP |
| 210 | 8080-8082 | 过渡期 `0.0.0.0/0`，之后只允许 155 内网 IP |

### 7. 管理端反代二战会绕一圈

家园管理端把二战管理接口反代到 `game_servers.host`，`:8081` 会被解析成
`http://127.0.0.1:8081` —— 也就是打到 nginx，再由 nginx 转给 18081。多一跳本地回环，
性能影响可忽略，但排查时看到「nginx access.log 里有 127.0.0.1 的请求」是正常的。

### 8. nginx 成了单点 —— 必须自启

改造前玩家直连后端，改造后 155 上 6 个端口全过 nginx。nginx 一挂，主服和二战全挂。

```bash
systemctl enable nginx          # 开机自启（装完就做，别等出事）
systemctl is-enabled nginx
```

再配一条最小健康检查（可选，用 cron 每分钟）：

```bash
# /etc/cron.d/nginx-guard
* * * * * root curl -s -m 3 -o /dev/null http://127.0.0.1:8080/api/health || systemctl restart nginx
```

### 9. 210 上的二战实例，玩家实际已经走不到了

`game_servers.host` 是 `:8081`，前端用 `window.location.hostname` 拼地址 ——
玩家从 `155:8083`（210 家园）进来，hostname 还是 `47.102.48.155`，
点二战会跳 `155:8081`（155 的二战），**不会**跳到 210 的二战。

这是好事：所有玩家都在 155 的二战实例上，数据本来就同一个库。
210 的二战留着只有两个用途 —— ① 155 挂掉时容灾；② 210 家园管理端反代。
所以**别停它**（停了 210 家园管理端的二战菜单会 502），但也别指望玩家会用它。

## 八、备选：不想动 155 端口的最小改动版

如果不想让 155 停服 30 秒改端口，可以只做一半：

- 155 的 8080/8081/8082 **保持后端直连**，nginx 不占
- nginx 只监听 8083/8084/8085，把 210 的服务挂到 155 上

玩家还是记 `155:8080` + `155:8083`，体验一样。
代价是以后想上域名 / HTTPS / 限流，155 本机那三个端口得再改一次。

**建议**：如果确定短期不上域名，先用这个；如果打算以后上 HTTPS，一次做到位（主方案）。
