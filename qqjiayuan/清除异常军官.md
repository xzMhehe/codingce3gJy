# 清除异常军官报告（2026-10-09）

> **用户规则**（原话）：
> ① 线上玩家军官超过参谋部数量 bug 修复；
> ② 有玩家反馈修改将领名字能卡数量 bug → 玩家相同城市同名军官只能有一个；
> ③ 清除多余的「5星以下」异常官；
> ④ 采集全部召回、出征也是全部召回；
> ⑤ 召回后物理清除多余的「5星以下军官（非名将）」。
> 补充确认：「删除五星以下多余的，按理说玩家城市军官数量不能超过当前城市参谋部等级，清理下不合理数据」。

---

## 一、根因定位（3 条产生「军官超编」的路径）

| # | 路径 | 问题 | 证据（线上） |
|---|---|---|---|
| 1 | **野地/寇城/活动守将可被反复俘虏** | `createCaptiveOfficer` 只卡「战俘营容量」，**没有「该玩家是否已拥有此守将」判断** → 同一守将被同一玩家连俘 N 次 | city 22「Pater·Wright」同 `general_id=1010` 被俘 **36 次**，间隔 30~60 秒 |
| 2 | **改名接口无同城重名校验** | `OfficerRename` 只校验长度 2~12，**不查同城是否已有同名** | 全服 201 组同城重名 |
| 3 | **军校招募 / 俘虏收编不查同城同名** | `hireOfficerDraft`、`recruitCaptive` 只卡参谋部容量，不查重名 | 同上 |

**为什么「超编」和「改名卡数量」是同一个根因**：
所有「按名字找军官」的玩法（`officerByName` / `officerBusyOrder` / 出征带队 / 忠诚结算）都只认**第一行**同名记录，
于是产生了「军官表里几百行、界面只显示 1 个 / 军官位永远不涨」的**「卡数量」错觉** ——
玩家能无限刷同名军官，但玩法层只看到 1 个。

## 二、代码修复（6 处，已通过 `go build` + 20 条单测）

新增统一口径函数 `ezfyOfficerNameTaken(cityId, name, excludeOfficerId)`（`ezfy_officer.go`）：
按 **`city_id + name`** 查重，可排除自己。

| 入口 | 函数 | 加的卡控 |
|---|---|---|
| 野地/寇城/活动守将俘虏 | `createCaptiveOfficer` | **同城已同名 → 直接跳过**（不再制造重复；连战俘营空位都不占） |
| 改名 | `OfficerRename` | **同城已同名 → 拒绝**（"本城已有同名军官「X」, 请换一个名字"） |
| 军校招募 | `hireOfficerDraft` | **同城已同名 → 拒绝** |
| 俘虏收编 | `recruitCaptive` | **同城已同名 → 拒绝**（排除自己） |
| PvP 归降收押 | `defectDefenderOfficers` | **攻方城已同名 → 不收押**（原军官按规则离城） |
| 军官派遣（跨城） | `OfficerDispatch` | **目标城军官位满 或 已同名 → 拒绝**（原先完全不卡目标城） |
