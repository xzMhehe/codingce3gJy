# 游戏索引（二战风云）

> 二战风云（ezfy）热接口的复合索引。首页 `/view` 30s 轮询的命令数/未读战报计数、装备检索，
> 只靠单列 `user_id` 会在引擎窄化后再过滤，补带 `status/is_read` 的复合索引直接命中。
> 双机共享同一个 RDS（阿里云上海，库 `qq_jiayuan`），建一次全局生效。
> GORM(model) + AutoMigrate 只保证补列/主键，普通复合索引需显式执行下面的 `ALTER`。

## ezfy_order — 命令表

命令计数（行进/驻守）、采集/闲置采集订单列表均按 `user_id + status(+order_type)` 过滤。

```sql
ALTER TABLE ezfy_order
  ADD INDEX idx_order_user_status (user_id, status, order_type);
```

## ezfy_report — 战报表

未读战报计数、战报列表按 `user_id + is_read` 过滤。

```sql
ALTER TABLE ezfy_report
  ADD INDEX idx_report_user_read (user_id, is_read);
```

## ezfy_equipment — 装备背包表

宝物持有量、背包装备检索按 `user_id + cfg_id (+officer_id)` 过滤。

```sql
ALTER TABLE ezfy_equipment
  ADD INDEX idx_equip_user_cfg_off (user_id, cfg_id, officer_id);
```

## 幂等性

以上 `ALTER ... ADD INDEX` 若索引已存在会报 `Duplicate key name`，重复执行无害；已按
`information_schema.STATISTICS` 判存在再建（见 `seed/ezfy.go ensureEzfyIndex`），部署新二进制会自动建。
