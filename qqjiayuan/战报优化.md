# 战报优化（战斗报告清理 + 索引）

> 目的：`ezfy_report`（战报，35MB+）和 `ezfy_battle`（战斗，15MB+）是备份里最大的两张表。
> 大量 3 天前的旧战报/旧战斗历史越攒越多，先补 `created_at` 索引让清理 DELETE 走索引直接命中，
> 再删除 3 天前的历史数据，一次把备份体积压下去。
> **线上、本地库都要执行同一套 SQL。**
>
> 索引：线上/本地分散执行即可，已存在会报 `Duplicate key name`，无害（可先查 `information_schema` 判存在）。
> 若希望部署时自动补索引，可仿照 `seed/ezfy.go` 的 `ensureEzfyIndex` 加入种子（见文末）。

---

## 一、加索引

### ezfy_report — 战报表

按 `created_at` 过滤删除旧战报：

```sql
ALTER TABLE ezfy_report
  ADD INDEX idx_report_created (created_at);
```

### ezfy_battle — 战斗表

按 `updated_at` 过滤删除旧战斗历史：

```sql
ALTER TABLE ezfy_battle
  ADD INDEX idx_battle_created (created_at);
```

> **为什么只建时间索引就够**：清理 DELETE 不带 `user_id` 过滤（跨全库删 3 天前旧数据），
> 索引前导列必须是 `created_at`/`updated_at` 才能命中范围扫描。若建 `(user_id, created_at)`
> 复合索引，清理 SQL 没有 user_id 条件，前导列用不上，索引会失效退化回全表扫 —— 反而更糟。
>
> 玩家按用户翻战报（`WHERE user_id = ? ORDER BY id DESC LIMIT 200`）由现有
> `idx_user(user_id)` + `idx_report_user_read(user_id,is_read)` 覆盖，与清理索引互不干扰。
> 若还想要按用户翻最近战报「免排序」，可另加（和清理索引是两件事，不要替换时间索引）：
>
> ```sql
> ALTER TABLE ezfy_report
>   ADD INDEX idx_report_user_id_desc (user_id, id);
> ```

## 二、清除 3 天前的战报/战斗

> `3 DAY` 即 72 小时。联动：`ezfy_battle` 的旧战斗（创建/更新时间在 3 天前）也已结束，
> 玩家视角单看 `ezfy_report` 战报；后台攻打历史才读 `ezfy_battle`，清掉不影响在打的新战斗。

### 分批删除（推荐，避免大事务/锁/binlog 峰值）

一次 `DELETE` 删几万行会产生大事务、长锁、binlog 暴涨。**按主键 id 从小到大分批删**，
每批 `LIMIT 1000`，删到影响行数为 0 为止：

```sql
-- ezfy_report：循环执行同一条，直到受影响行数 = 0
DELETE FROM ezfy_report
 WHERE created_at < DATE_SUB(NOW(), INTERVAL 3 DAY)
 LIMIT 1000;
```

```sql
-- ezfy_battle：循环执行同一条，直到受影响行数 = 0
DELETE FROM ezfy_battle
 WHERE updated_at < DATE_SUB(NOW(), INTERVAL 3 DAY)
 LIMIT 1000;
```

> 说明：
> - 每批都走 `idx_report_created` / `idx_battle_created` 时间索引；批间 `COMMIT` 自动完成，锁和 binlog 峰值都小。
> - 每执行一次物理删掉 ≤1000 行，重复执行同一条即可清完，直到 `affected rows = 0`，不会死循环（行被删掉了，不会重复命中）。
> - 数据量不大（几万行内）时命令行客户端里手动循环几次即可；要一条命令跑完可用存储过程/脚本（见文末）。

### 一条 SQL 直接删（量小可选）

> 数据量小（≤几万行）、能接受单条大 DELETE 时可直接执行，功能相同：

```sql
DELETE FROM ezfy_report
 WHERE created_at < DATE_SUB(NOW(), INTERVAL 3 DAY);

DELETE FROM ezfy_battle
 WHERE updated_at < DATE_SUB(NOW(), INTERVAL 3 DAY);
```

## 三、执行顺序与校验

1. **先加索引再删**（否则全表扫描慢）。
2. 删除后核对剩余量：

```sql
-- 删前
SELECT COUNT(*) AS report_cnt FROM ezfy_report;
SELECT COUNT(*) AS battle_cnt FROM ezfy_battle;

-- 验证 3 天前还有没有残留
SELECT COUNT(*) AS old_report FROM ezfy_report
 WHERE created_at < DATE_SUB(NOW(), INTERVAL 3 DAY);
SELECT COUNT(*) AS old_battle FROM ezfy_battle
 WHERE updated_at < DATE_SUB(NOW(), INTERVAL 3 DAY);
```

3. 确认 `old_report` / `old_battle` 为 `0`，再重新导出备份，体积应大幅下降。

## 四、部署自动建索引（可选）

线上/本地若已手动加过索引则跳过；想做到启动即幂等补建，
把下面两句放进 `server/internal/seed/ezfy.go` 的 `seedEzfy()`（复用现有 `ensureEzfyIndex`）：

```go
ensureEzfyIndex(db, "ezfy_report", "idx_report_created", "created_at", false)
ensureEzfyIndex(db, "ezfy_battle", "idx_battle_created", "created_at", false)
```

清理 DELETE 建议用定时任务/手动执行，不放进启动流程。

## 五、一条命令跑完分批删除（可选）

> 不想手动循环时，用下面这个存储过程自动分批删（调用一次跑完，批内 `LIMIT 1000`）：
> 线上/本地各执行一次 `CALL purge_old_reports();` 即可。重复调用幂等。

```sql
DROP PROCEDURE IF EXISTS purge_old_reports;
DELIMITER $$
CREATE PROCEDURE purge_old_reports()
BEGIN
  DECLARE n INT DEFAULT 1;
  WHILE n > 0 DO
    DELETE FROM ezfy_report
     WHERE created_at < DATE_SUB(NOW(), INTERVAL 3 DAY)
     LIMIT 1000;
    SET n = ROW_COUNT();
  END WHILE;

  SET n = 1;
  WHILE n > 0 DO
    DELETE FROM ezfy_battle
     WHERE updated_at < DATE_SUB(NOW(), INTERVAL 3 DAY)
     LIMIT 1000;
    SET n = ROW_COUNT();
  END WHILE;
END$$
DELIMITER ;

CALL purge_old_reports();
```
